Memory Games

A pile of tiny browser games that train working memory. Each round picks a random game, lasts 30 seconds, and keeps a personal high score in localStorage.

Open index.html — no build step, no dependencies.

Games

Grouped by mechanic. Everything in a group is the same code with different config, so a new theme costs about ten lines.

| Mechanic | Games | | --- | --- | | N-back | 1-Back Warm-Up, Adaptive N-Back, 2-Back Letters, 3-Back Shapes, Dual 2-Back | | Sequence recall | Shopping List Chain, Simon Sequence, Number Chain, Backwards Chain | | Card pairs | Card Pairs, Deep Space Pairs | | Object placement | Objects In A Room | | Probed recall | Which Was Where | | Complex span | Sums And Letters |

How it fits together

engine.js              round clock, scoring, high scores, random game picker
framework/util.js      shuffle/sample/flash + named icon sets
framework/a11y.js      live-region announcements + readable names for icons
framework/layout.js    boards that size themselves to the available screen
framework/nback.js     n-back mechanic (any N, any number of streams)
framework/sequence.js  growing-sequence mechanic + iconPad / padBoard themes
framework/pairs.js     concentration mechanic (board size + icon set as config)
framework/probe.js     partial report: hold a set, answer about one item
framework/complex-span.js  items interleaved with a judgement, then recall
games/*.js             one file per game, usually just a config object

The rule we work to: the second time we implement something, it moves into the framework. Single and dual n-back became one mechanic; the shopping list and Simon became one mechanic with two themes.

Adding a variation

Most new games are a config on an existing mechanic:

MG.register(MG.mechanics.pairs({
  id: 'pairs-space',        // storage key for the high score
  name: 'Deep Space Pairs',
  icons: MG.icons.space,
  pairs: 10,
  columns: 5
}));

Adding a new mechanic

Register a plain object. The engine owns the clock, the score display and cleanup — a game only builds its UI and calls ctx.add.

MG.register({
  id: 'my-game',
  name: 'My Game',
  mechanic: 'My Mechanic',   // groups it in the high score table
  start: function (ctx) {
    ctx.how('One line of instructions.');
    ctx.root.appendChild(/* your UI */);
    ctx.add(1);                       // award points
    ctx.after(500, fn);               // timers cleaned up at round end
    return function () { /* optional teardown */ };
  }
});

Then add a <script> tag in index.html.

What each mechanic actually demands

Different ways of forcing you to hold several items rather than one:

  • N-back — updating: the set to hold shifts every trial.
  • Sequence recall — cumulative order memory. order: can reverse the recall, so Backwards Chain makes you manipulate the set rather than replay it, which is a step up from rehearsal.
  • Card pairs / Objects In A Room — binding: what, plus where.
  • Which Was Where — partial report. Several items are shown and exactly one is probed, chosen afterwards, in either direction (what was here / where was this). You cannot know which, so the whole set has to be held, and one tap answers. Set size titrates 2–6.
  • Sums And Letters — complex span, the classic capacity measure. Letters to hold, an easy sum to judge in each gap. The sums are not the point: they occupy the moment you would spend rehearsing, so what is left is maintenance. Span titrates 2–6.

Choosing which games to keep

The point of building many is to keep the good ones, so the app collects the evidence for that rather than leaving it to memory:

  • A verdict prompt on the result panel — More of this / Meh / Not for me. It appears the first time you play a game and every fifth play after that. Asking every round would train you to dismiss it, and noise is worse than no data.
  • Plays and early quits are counted automatically. Abandoning a round with Stop is the strongest unprompted signal there is, and costs nothing to collect.
  • Games come from a shuffled bag, not an independent draw each round. Every game appears in every cycle, so nothing goes missing for a long stretch, and the same game never comes up twice in a row. Weight decides how many copies a game puts in the bag, so liking still shows up as frequency — liked games run about twice as often as disliked ones, and an unplayed game is favoured so new ones get a hearing.
  • The table on the intro screen shows best score, plays and verdict per game, so the picture is visible without digging into localStorage.

Weights use rates, not raw counts — a tally-based penalty keeps growing with play and eventually drowns out the ratings regardless of what you said. Caught by simulation: with counts, 4000 picks came out flat.

The bag deliberately caps how far preference can go. Copies run 1–4, so the strongest possible bias is 4:1, against roughly 15:1 for independent weighted draws. That is the trade for guaranteed coverage and no repeats; raise the copy ceiling in weightOf if you want preference to bite harder.

All of it is localStorage on the device. Nothing leaves the browser.

Difficulty and the n-back on-ramp

Fixed 2-back with a penalty for every miss is a wall: a beginner scores negative and learns nothing except that they are bad at it. The mechanic makes difficulty and pressure config instead:

  • 1-Back Warm-Up — hold one item, slower pace, a missed match costs nothing. The way to score is to spot matches, not to avoid mistakes.
  • Adaptive N-Back — starts at 1-back and follows you. Three clean trials with at least one real hit and it goes deeper; two slips and it eases off, so it settles just above what you can currently hold. Deeper levels pay more.
  • floor: 0 keeps the visible score off negative, but the unpaid penalty is held as debt and comes out of the next points earned — otherwise mashing the claim button would be free.
  • Levelling up needs a real hit, not just an absence of errors, so sitting out every trial does not push you deeper.

2-Back Letters, 3-Back Shapes and Dual 2-Back keep the strict scoring, so their high scores stay comparable with what they were.

Mobile and desktop

Every game has to work on a 320px phone and a 1920px desktop, so layout is a framework concern rather than a per-game one:

  • MG.layout.board(ctx, {cols, rows, ratio, maxCell}) measures what the stage has left after the instructions and controls, and sizes cells to fit. Boards fill a phone screen and grow on a desktop, up to maxCell.
  • Tap targets are never smaller than 44px.
  • The page uses 100dvh and safe-area padding, and never scrolls during a round — a control you have to scroll to reach is a lost point.
  • Double-tap zoom, tap highlight and text selection are off; hover styles apply only to real pointers; keyboard hints hide on touch devices.
  • Landscape phones get a compact header and a sideways layout.

Accessibility

These games are colour, position and emoji, so accessibility is built into the framework rather than retrofitted per game:

  • MG.a11y.say() announces through a polite live region — what was shown, what a claim scored, whose turn it is, and the time checks at 10s and 5s. Every game is playable listening rather than looking.
  • MG.a11y.name() turns an icon into words, so a card reads as "row 2, column 3, apple" instead of an unlabelled button.
  • Nothing is signalled by colour alone: the Simon pads carry a symbol as well as a colour, and every flash is accompanied by an announcement.
  • Focus is managed across the round: into the game when it starts, onto the result panel when it ends, never dropped on the document.
  • Contrast meets 4.5:1, with prefers-contrast, prefers-reduced-motion and Windows forced-colors all handled.

Tests

npm i
npm run serve &     # http://localhost:8765
npm test            # smoke + layout

test/smoke.mjs drives every registered game in a real browser and fails on any console or page error. test/layout.mjs replays all of them across six viewports and fails on horizontal overflow, mid-round scrolling, off-screen controls or tap targets under 44px. test/a11y.mjs runs axe on every game and then checks the things axe cannot: accessible names on iconic controls, keyboard reachability, focus handling at both ends of a round, and that the game actually announces itself.

CI runs all three on every push, and only a commit that passed them is published to Pages.
