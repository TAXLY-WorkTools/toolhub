yabridge compatibility tracker

unofficial · crowd-sourced · not affiliated with yabridge

There's no ProtonDB for yabridge. This is a manually compiled read of what's floating around forums and the yabridge GitHub, cross-checked for how many independent sources actually back each entry.

This table is an index. Each plugin has a page with the dated reports behind it, the host DAW and Wine or yabridge versions involved, and the fixes that were needed — the detail that would make this table unreadable.

Read this first

What this is: second-hand reports, collected by hand, about software none of the people here maintain. It is a starting point for your own testing, not a compatibility guarantee.

Where it will be wrong:

  • Nobody here retested these plugins. Almost every entry summarises what someone else wrote, often years ago. Every source now cited has been opened and read — two forum threads only through the Internet Archive, because the live sites are behind bot challenges. Where a claim could not be traced to a source that opens, it was withdrawn, and the page says so.
  • Compatibility is version-bound and moves fast. A row is only about the Wine, yabridge, plugin and host versions named on its page — and a fix on yabridge's master branch is not in a release. Your combination is probably different.
  • verified means two independent people reported the same thing. It does not mean anyone confirmed it on your distribution, your host, or your hardware.
  • confirmed broken means broken in the reports we found. A vendor or Wine update may have fixed it since; a working plugin may have broken since.
  • Check each page's last checked date before trusting it.

Don't buy a plugin on the strength of a row here. Use the vendor's trial, and ask the vendor about Linux and Wine before paying. Very few of these vendors support Wine at all, and using their plugins this way may fall outside their terms — that is between you and them.

Not affiliated with, endorsed by, or speaking for yabridge, WineHQ, or any plugin vendor named here. Product and brand names belong to their owners; they appear only to identify what a report is about. No warranty, express or implied.

Found something wrong or out of date? That's the useful contribution — open an issue or a pull request.

Scope

In scope: Windows audio plugins running on Linux through a translation layer — yabridge above all, and plain Wine or LinVst where a report covers them. That is where the information is scattered, contradictory and undated, which is the only reason this database earns its keep.

Out of scope: cataloguing native Linux plugins. Not because they don't matter — they are usually the better answer — but because the question "does this ship a Linux build?" already has an authoritative answer on the vendor's own page, and the lists below already do the cataloguing:

  • Linux Audio applications index — over 1,500 indexed entries, alphabetical
  • awesome-linuxaudio — curated LV2, LADSPA and VST plugins alongside hosts and utilities

Nothing here needs two independent sources: a vendor either ships a Linux build or it doesn't. Verification is for claims nobody official will make.

Where the two meet: when a plugin already in this table also has a native Linux build of the same product, its page says so under Native alternative, because the best outcome of landing on one of these rows is finding out you don't need to bridge anything. That's a note on an existing row, not an invitation to add rows for plugins that were never bridged.

Legend

  • verified — 2+ independent sources
  • reported — single source only
  • confirmed broken — does not work

A source is a report you can open and read: a GitHub issue, a forum post, a CHANGELOG entry. yabridge's own README and CHANGELOG count as one source between them, since they are one project's voice. Vendor testimonials are not sources.
